# 本轮流程优化与验收

状态：全库合同审查、修复、本地回归和代表性模型验收已完成，共七次真实调用。整体效率提升证据不足，自动跨语言与原生宿主交互仍有未验证项；入库状态见 PR #8。本文记录本轮任务结果，不修改规范源文件的权威关系。

## 基线与范围

开始优化前，既有源码已与远端核对，遗留研究和审计记录通过 [PR #7](https://github.com/yknothing/prodcraft/pull/7) 入库。本地与远端 `main` 同为 `f32950759a6c86bd4b1b63590d7cc230cec98cb1`，工作区干净。基线通过 508 项测试及 GitHub 检查。

首批优化实现已提交为 `80252f9a8ead86d811b11f30abc2c9502d637ee9`，推送至 [PR #8](https://github.com/yknothing/prodcraft/pull/8)。该实现提交的 [GitHub validate-structure 检查](https://github.com/yknothing/prodcraft/actions/runs/37016100263/job/110867222257) 已通过。用户随后明确授权模型对照，并要求全库优化和验收；本轮补审沿同一 PR 收口，最终入库状态以该 PR 为准。

本轮沿用现有入口、技能、交接记录和权限边界；未增加技能、调度器、依赖或平行状态系统。七个修改包均为 `review`；其中 `pc-acceptance-criteria` 从 `tested` 回到 `review`，旧版本证据与成熟度保留。全库当前为 34 个 `review`、12 个 `tested`、0 个 `production`。

## 实际改动

- **可读记录**：任务记录的正文、标题和反馈按当前实质请求的语言输出；显式指定记录语言优先。机器字段、枚举、已有引用和历史证据保持稳定。以有意义的标题为主，只有需要追踪时才附带编号。三类记录允许已有 locale 格式，旧英文记录仍可校验。
- **轻量入口**：`micro` 从 19 个顶层必填字段（18 个通用字段加资格声明）缩到 10 个；质量上下文从 5 个字段缩到运行环境和暴露范围。五项资格声明仍全部为真，公共服务和公网暴露仍不适用。其他模式的原有必填要求保持不变。
- **Claude adapter 边界**：保存 micro 记录只记录决策，不提供写权限。实际 `Edit`/`Write` 返回宿主 `ask`；草稿、非法字段、未知技能、别名和校验失败继续阻止写入。严格执行模式的外部 pins 和授权机制未改变。
- **交接复用**：入口负责路线和授权边界，工作流负责顺序和门禁，专业技能负责具体决策与证据。在现有任务记录内传递有效结果的位置、版本、限制和下游验收条件；缺少某个事实时退回其生产者，变动只使依赖它的结论失效。轻量质量检查直接消费摘要中的目标和检查依据。

## 独立评审发现与修复

1. 旧路由示例和中文指南仍要求在 Claude adapter 下将 micro 升级为 fast-track；已同步活跃说明，历史设计记录保留时间边界。
2. 质量入口与代码评审、测试策略消费者无条件要求完整质量上下文，会使精简失效；已统一适用条件。安全审计保留原有完整输入合同，安全相关变动仍不能使用 micro。
3. canonical intake 与另一文件共享硬链接 inode 时，控制记录写入可能影响另一文件；已拒绝共享 inode，新增真实校验器回归。
4. 校验期间普通写入目标变成 intake 的别名时，原先只在校验前检查；已在校验后复查目标。这一缺口在旧版本已存在，不能说成本轮新引入。hook 返回与宿主真正写入之间仍不能原子绑定。
5. 问题澄清技能没有明确继承“交流语言与记录语言分别指定”的例外；已补齐，不增加新的语言字段。
6. 验收标准技能无条件要求 QA 团队审批、把详细规格当作必需输入，与单人敏捷路线冲突；现按已批准路线和项目要求确定 reviewer，复用有效需求片段，明确自审不能替代所需独立审批。
7. 活跃规则将固定小集合也强制分页、将示例性能数字当成默认要求、将非可执行修订也要求代码 RED；已分别按真实集合边界、有来源的目标和实际验证层次校准。未知指标保留负责人，不捏造阈值。
8. 质量阶段要求先合并再进入评审，演进阶段要求至少三项行动并默认承诺容量，技术设计模板要求清空所有未决问题；现分别改为评审先于合并、允许有证据的无新行动和待分配容量、只阻塞依赖该问题的实现切片。

评审者独立重放了两项文件别名问题，修复后均返回阻止结果。对 full/resume/fast-track 逐一删除原必填字段及检查 workflow 条件的 72 个对照探针，旧版与新版判定一致。

## 真实模型对照

用户授权后，Codex CLI 0.159.0 对三个固定虚构任务分别加载冻结的旧版和首轮候选指导，共六次调用，无超时。请求模型为 `gpt-6.1-sol`；CLI 事件没有独立披露实际服务模型标识。每种条件一次、两路并发，不构成统计结论；这是新的消费者会话，未测试原生会话恢复。首轮候选对应 `80252f9` 的六个通用文件；后续仅调整其中的功能实现 I/O 说明，并追加下面的第七次复验，未覆盖或回写首轮结果。另两个任务只加载入口四文件，它们仍与最终源码一致。

| 相同任务 | 旧版 / 候选耗时 | 实际结果 |
|---|---:|---|
| 中文单行文档修订 | 62.689 / 63.226 秒 | 两版只改指定拼写，记录均过各自 schema；候选记录正文为中文，顶层字段 19→10、质量字段 5→2、记录字符 1,420→802 |
| 复用已确认双文件功能 | 81.245 / 110.886 秒 | 两版实现正确，没有重问已批准条件或新增计划文件；候选把英文交接写回原 task.md，文件 615→4,160 字符，增加了文书与耗时 |
| 分页依赖变动与生产动作边界 | 29.909 / 28.458 秒 | 两版复用列与编码约定、复查分页依赖并拒绝未授权生产删表/发布；均未调用工具或产生文件 |

功能产物由主评审独立重跑各 3 项测试，并核对 Unicode casefold、默认/位置参数、truthy/falsy、缺失字段、顺序、对象引用、空输入及输入不变性，均通过；独立评审另行检查原始产物。四份入口记录按各自冻结 schema 均合法。候选按显式要求采用英文记录、中文反馈。

英语风险场景两版都回复中文。当前宿主全局指令要求中文，`--ignore-user-config` 和 `--ignore-rules` 不会移除这类指令文件；因此该场景存在语言干扰，不能据此通过自动语言切换验收，也不能把结果单独归因于候选版。没有修改用户全局指令。

三次调用耗时之和为 173.843→202.570 秒，工具调用 9→12，输出 token 3,044→3,943。输入 token 为 317,764→350,712，其中缓存 token 为 238,336→289,664；它们是 CLI 累计值，不能当作单次上下文大小。候选确实减少了 micro 字段并改善记录语言，但本样本没有证明总体提速或返工减少。功能任务较长的交接记录保留为负面观测，不以语义正确掩盖成本增加。

针对这条负面观测，最后精简了功能实现的交接要求：已有范围与批准只引用，只有路线要求时才持久保存相应记录，没有该义务时可在完成反馈中给出简短证据。独立评审确认没有删去必要审批或交接义务。第七次使用同一功能任务、最终六文件快照与相同请求模型：功能和真实测试再次通过，入口 schema 合法，英文记录/中文反馈符合要求。`task.md` 从首轮候选 4,160 降至 2,023 字符，耗时 104.798 秒、9 次工具调用、2,085 个输出 token；仍未优于旧版的 81.245 秒。此项只证明本次样本文书减少，不能证明统计意义的提速。

Gemini CLI 0.39.1 的固定探针被当前账户策略拒绝，返回 `IneligibleTierError`；其原生包解析仍单独通过。七次正式调用使用经用户授权的通用流程文件和虚构任务，没有使用真实审批状态或 pins。冻结源码摘要、原始事件、产物和独立评分保留在本地 `build/2026-10-02-workflow-efficiency/`；主评审与独立评审均复验了实际功能产物。

本轮不将静态字段减少、源码字符数或测试通过等同于总体返工率下降。此前的单任务对照仅作为[历史证据](2026-09-11-strict-host-closure.md)；本轮真实效率结论必须以新观测为准。
