# 本轮流程优化与验收

状态：实现、独立评审修复和本地验收通过；真实模型对照等待用户外发授权，整体效率收益未作通过结论。本文记录本轮任务结果，不修改规范源文件的权威关系。

## 基线与范围

开始优化前，既有源码已与远端核对，遗留研究和审计记录通过 [PR #7](https://github.com/yknothing/prodcraft/pull/7) 入库。本地与远端 `main` 同为 `f32950759a6c86bd4b1b63590d7cc230cec98cb1`，工作区干净。基线通过 508 项测试及 GitHub 检查。

本轮沿用现有入口、技能、交接记录和权限边界；未增加技能、调度器、依赖或平行状态系统。修改后的技能维持 `review`，不以本轮局部验收提升成熟度。

## 实际改动

- **可读记录**：任务记录的正文、标题和反馈按当前实质请求的语言输出；显式指定记录语言优先。机器字段、枚举、已有引用和历史证据保持稳定。以有意义的标题为主，只有需要追踪时才附带编号。三类记录允许已有 locale 格式，旧英文记录仍可校验。
- **轻量入口**：`micro` 从 19 个顶层必填字段（18 个通用字段加资格声明）缩到 10 个；质量上下文从 5 个字段缩到运行环境和暴露范围。五项资格声明仍全部为真，公共服务和公网暴露仍不适用。其他模式的原有必填要求保持不变。
- **Claude adapter 边界**：保存 micro 记录只记录决策，不提供写权限。实际 `Edit`/`Write` 返回宿主 `ask`；草稿、非法字段、未知技能、别名和校验失败继续阻止写入。严格执行模式的外部 pins 和授权机制未改变。
- **交接复用**：入口负责路线和授权边界，工作流负责顺序和门禁，专业技能负责具体决策与证据。在现有任务记录内传递有效结果的位置、版本、限制和下游验收条件；缺少某个事实时退回其生产者，变动只使依赖它的结论失效。轻量质量检查直接消费摘要中的目标和检查依据。

## 独立评审发现与修复

1. 旧路由示例和中文指南仍要求在 Claude adapter 下将 micro 升级为 fast-track；已同步活跃说明，历史设计记录保留时间边界。
2. 质量入口与代码评审、测试策略消费者无条件要求完整质量上下文，会使精简失效；已统一适用条件。安全审计保留原有完整输入合同，安全相关变动仍不能使用 micro。
3. canonical intake 与另一文件共享硬链接 inode 时，控制记录写入可能影响另一文件；已拒绝共享 inode，新增真实校验器回归。
4. 校验期间普通写入目标变成 intake 的别名时，原先只在校验前检查；已在校验后复查目标。这一缺口在旧版本已存在，不能说成本轮新引入。hook 返回与宿主真正写入之间仍不能原子绑定。
5. 问题澄清技能没有明确继承“交流语言与记录语言分别指定”的例外；已补齐，不增加新的语言字段。

评审者独立重放了两项文件别名问题，修复后均返回阻止结果。对 full/resume/fast-track 逐一删除原必填字段及检查 workflow 条件的 72 个对照探针，旧版与新版判定一致。

测试先复现旧行为的失败，再验证修复。独立评审另行执行 28 项窄测试、72 个非 micro 合同对照探针及真实文件别名重放。部分集成测试会主动模拟重试，这是本地测试用例，不是成功的外部模型调用。

模型对照准备了三个固定的虚构任务，分别使用冻结的旧版与候选指导：中文单行文档修订、复用已确认条件的双文件功能、依赖变动与高风险动作的路线判断。每种条件一次，不构成统计结论。源码和输入摘要、原始日志保留在本地 `build/2026-10-02-workflow-efficiency/`。

Gemini CLI 0.39.1 的固定探针被当前账户策略拒绝，返回 `IneligibleTierError`；Codex CLI 0.159.0 的固定 READY 探针成功。正式对照尚未执行：自动审批审查要求用户明确授权将未发布的候选改动发送给现有 OpenAI Codex/ChatGPT。公开仓库属性和 CLI 登录方式已核实，未将探针成功算作技能行为验收。

本轮不将静态字段减少、源码字符数或测试通过等同于总体返工率下降。此前的单任务对照仅作为[历史证据](2026-09-11-strict-host-closure.md)；本轮真实效率结论必须以新观测为准。

## 回退与剩余边界

通过独立提交撤销源文件/schema/adapter 改动后重新生成 `.curated/`，保留历史证据。微小任务仍依赖正确的风险判断；宿主确认与独立评审不能由 agent 自写 approver 字段替代。源码入库、全局安装、宿主实际交互和统计意义上的效率提升分别验收。
