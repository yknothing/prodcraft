# pc-debug-expert 设计说明（中文导读）

日期：2026-09-13。本文是非权威中文导读；规则与验收记录以[英文设计](2026-09-13-debug-expert-design.md)和 [Skill 源文件](../../skills/04-implementation/pc-debug-expert/SKILL.md)为准。

本次撤回独立的 `debug-expert` persona，将现有 `pc-systematic-debugging` 改名并完善为 `pc-debug-expert`。保留一个 Skill，集中承载专家判断、方法和执行支持。

顶级调试专家的目标是：面对软件故障，得到最有依据的下一步行动，可能是因果修复、安全缓解，或可由其他工程师继续的有限诊断。简单问题可以用一个决定性检查解决；复杂问题才需要逐步构建系统模型与竞争解释。

## 能力、思维与可观察表现

| 能力 | 专家怎样思考 | 应当看到的实际行为 |
|---|---|---|
| 准确界定故障 | 用户的哪项预期被破坏？报错和测试断言是否准确表达它？ | 明确预期、实际、影响对象、触发条件和风险，必要时修正错误的测试判定 |
| 还原系统与运行状态 | 数据、控制、状态、时间和责任如何跨越边界？ | 确认实际运行版本、入口、调用路径和状态所有者，区分旧产物、路径未执行和日志不可见 |
| 建立有效反馈 | 这个检查能否捕捉真实故障？精简后是否仍保留故障机制？ | 在未修复行为上确认检查敏感，保留必要的并发、权限、状态和负载条件 |
| 形成与修正解释 | 哪些解释还成立？什么证据会推翻当前判断？ | 区分观察、推断和干预；主动查找反证，不把历史相似性或未观察到证据当成证明 |
| 选择有信息价值的实验 | 哪个可执行检查的不同结果会改变下一步？成本与扰动是否合理？ | 先写预测与分支，再选择能区分解释的检查；停止重复无信息增量的动作 |
| 理解因果与交互 | 触发因素、必要条件、传播过程和未被保护的约束分别是什么？ | 找到首次偏离正确状态的边界，验证联合条件，区分新回归、被暴露的旧问题和原问题改变表现 |
| 选择正确修复位置 | 在哪个可控边界恢复约束，才能保持兼容并避免转移问题？ | 修复可控的生产者；面对外部输入或不可控依赖，在接收边界建立合理校验或明确的临时措施 |
| 完成验证并转移知识 | 结论由哪些证据支持？下一位工程师能否继续而不重复踩坑？ | 同一条件下关联修复前后证据，检查邻近风险，留下未决解释、有效反证和下一项判别检查 |

## 原则与纪律

- 保持好奇与怀疑。经验帮助提出检查，不能替代当前故障的证据。
- 因果表述要精确。恢复服务、版本相关性和单次通过，都可能对应多种原因。
- 理解整个相关系统，再选择修复边界。修改次数本身不能证明架构有错。
- 优先选择低扰动、有区分力的检查。复杂故障可以用小规模组合实验验证因素交互，不机械坚持每次只改一个变量。
- 事故中优先保护用户并保存证据。可以同时做安全的被动诊断，不为证明原因而恢复生产危害。
- 缺少源码、测试、历史记录或主动访问权限时，继续能独立推进的调查，准确限定受影响的结论。
- 不编造置信度百分比，不要求固定数量的假设，不额外制造 persona、进程或每次实验的审批。
- 修复要恢复用户真正需要的行为，并检查相关兼容性、失败路径和残留资源。

## 这些能力如何进入 Skill

主文件保留按不确定性调整的决策循环、输入边界和完成标准。现有 `references/techniques.md` 提供按需读取的具体方法：有效反馈、实验选择、约束追踪、二分与差异分析、运行环境与 Skill 加载、并发异步、性能、多原因故障、修复位置。

例如，多租户缓存串数据，必须保留两个租户和共享缓存；单租户测试变绿并没有验证真实问题。再如，新日志没有出现，先区分运行版本、路径到达和日志通道，再决定是否需要重建。修复后出现另一个错误，要用版本与触发条件对照判断，不能直接当作另一个 bug。

调查记录沿用 `bug-fix-report` 或项目已有记录。复杂调查保留预测、结果、有效反证、证据来源和下一项判别检查，支持中断后继续；不新增强制表单。

## 迁移与证据边界

当前源码、路由、工作流、产物消费关系和公开包统一使用 `pc-debug-expert`，不保留第二个旧名 Skill。旧评测目录和封存结果仍保留原来的 `pc-systematic-debugging` 身份，避免把旧版本结果冒充新设计验证。

本次修改范围是仓库。已有全局安装不会自动改名；安装新包时需要迁移旧名调用。新的 Skill 保持 `review`，当前设计是否提升真实排障效果、是否超越其他 Skill，仍需有效的实操对照验证。后续评测应让 agent 自己找证据和完成修复，不提前给出根因答案。

本地验收已完成：508 项仓库测试通过；46 个源码 Skill 和 40 个公开包通过 Gemini CLI 原生文件解析；58 个历史评测文件内容未变。描述为 215 字符，结构、引用、上下文预算和独立合同审查均通过。这些结果支持设计与迁移的本地验收，不代表宿主已安装新包或已证明排障能力增益。
